# GitHub Fork 自动同步管理器 技术架构与实施白皮书

## 一、系统总体架构

GitForkSync 采用前后端分离、单进程部署的轻量化 Windows 本地运行架构：

```

|                         用户浏览器 (Web GUI)                             |

                                   | (HTTP/JSON 127.0.0.1:3847)
+-------------------------------------------------------------------------+
|                    Fastify 4 本地应用服务器 (TypeScript)                  |
|                                                                         |
|  +--------------------+  +--------------------+  +--------------------+ |
|  |   GitHub 认证模块   |  |   仓库发现模块     |  |   提交比较引擎     | |

|  +--------------------+  +--------------------+  +--------------------+ |
```

## 二、分支比较引擎核心算法

### 1. 比较方向约定
- `BASE = 我的目标分支`（例如 `upstream-sync` 或 `main`）
- `HEAD = 上游目标分支`（例如 `upstreamOwner:main`）

在这个约定下：
- `ahead_by`：表示上游独有的提交数（上游比我领先多少）。
- `behind_by`：表示我方目标分支独有的提交数（我有多少独立修改未合入上游）。

### 2. 六种分支拓扑状态判定矩阵

| 状态 | ahead_by | behind_by | 共同祖先 | 处理动作 | 安全性保障 |
|---|---|---|---|---|---|
| **up_to_date** (已是最新) | 0 | 0 | 存在 | 不操作 | SHA 完全一致，无需任何写入 |
| **behind_safe** (安全落后) | > 0 | 0 | 存在 | **自动安全快进同步** | 允许纯 Fast-forward，不产生任何冲突 |
| **ahead** (我方领先) | 0 | > 0 | 存在 | 不操作 | 仅自己做了改动，上游无变化 |
| **diverged** (分支分叉) | > 0 | > 0 | 存在 | **暂停同步，人工处理** | 双方均有提交，禁止自动合并以防破坏代码 |
| **incompatible** (历史不兼容) | - | - | 不存在 | **暂停同步，人工处理** | 无共同祖先树，拒绝盲目合并 |
| **unknown** (历史异常) | - | - | - | **暂停同步，人工确认** | 上游 Rebase 或 Force Push 标志 |

## 三、安全 Git 同步流程

1. **获取仓库互斥锁**：同一仓库在任意时刻只允许单个任务执行。
2. **二次状态核验**：推送前重新调用 GitHub API 校验 SHA 与分叉状态。
3. **隔离工作区**：在 `%LOCALAPPDATA%\GitForkSync\temp\<taskId>` 建立专属临时 Git 目录。
4. **受控 AskPass 认证**：Git 命令行中绝不拼接 Token，通过环境变量管道传入。
5. **拉取与目标 SHA 校验**：执行 `git fetch upstream <branch>`，核验 `FETCH_HEAD` SHA。
6. **非强制推送**：执行 `git push origin FETCH_HEAD:refs/heads/<targetBranch>`（**绝对禁止 `--force`**）。
7. **远程 API 二次查验**：通过 GitHub API 重新读取远程目标分支 SHA，核验是否完全一致。
8. **清理与释放锁**：删除临时目录，释放仓库锁，记录持久化日志。
